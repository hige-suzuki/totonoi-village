# ととのい村 画像生成ルール

## 1. 基本方針

- リポジトリ内の正式資料を確認してから生成する。
- 文章仕様と正式画像が矛盾する場合は、各仕様書が指定する優先順位に従う。
- 新しい造形、衣装、地理、施設または設定を画像生成AIに勝手に補完させない。
- 未確定事項が必要になった場合は、生成前に提案と正式採用を分ける。
- `review` 配下の画像を正式基準として使用しない。

## 2. SNS（X）漫画の出力形式

- 基本は4コマ漫画とし、必要に応じて1コマ完結も使用する。
- 4コマ漫画は1コマにつき画像1枚として個別に生成し、各画像は正方形とする。
- 4コマを1枚へまとめず、各画像の内部へコマ枠を描かない。
- 同一話では時間帯、光、色調、線、質感および背景世界の表現を統一する。
- 最終採用画像は、話数とコマ番号が分かる安定したファイル名で保存する。

## 3. 正式参照画像

- キャラクターは `assets/characters/<character>/<phase>/<category>/reference/` の正式画像を優先する。
- Phase 1は素体、基本形、顔、配色およびシルエットの基準とする。
- Phase 2は正式衣装、仕事着、私服、サウナ衣装、表情およびポーズの基準とする。
- 相対サイズは `assets/characters/comparison/reference/totonoi_village_character_size_comparison_v1.0.png` を基準とする。
- 耳や羽角などを除いた頭部本体高で比較し、衣装やポーズで素体の基準サイズを変えない。

## 4. キャラクター造形

- 正式画像の頭身、体格、顔、配色、種族固有構造および識別要素を維持する。
- 性別を明確にする要素や写実的な毛並みを追加しない。
- 全キャラクター共通で独立した手を描かない。
- 腕先は滑らかな丸みで閉じ、指、親指、手のひら、手首、爪、肉球、関節線または握り拳を描かない。
- 物を持つ場合は丸い腕先と物体を重ねて表現する。
- 翼などの種族固有構造は個別仕様と正式画像を優先する。

## 5. 時系列と衣装

- `TIMELINE.md` を優先し、サウナ完成前と完成後を混同しない。
- サウナ誕生前はサウナ棟、食堂棟、渡り廊下、サウナ設備およびサウナ用看板を描かない。
- サウナ誕生前のビーバーは「ビーバーさん」と呼び、サウナ店長衣装を着用させない。
- サウナ誕生前のリスルにスタッフ制服を着用させない。
- 衣装が正式画像で確定している場合は、その衣装を変更しない。

## 6. 村の地理と視点

- 地理は正式地図および施設見取り図を優先する。
- 正式地図を背景参照に使う場合、地図をそのまま俯瞰イラストへ変換しない。
- 物語内のカメラ位置と向きを先に定め、その場所に立った視線で実際に見える範囲だけを描く。
- 遠近、遮蔽物、建物の重なり、植生および地形によって見えない場所は描かない。
- 村全体を説明する必要がない場面では全景や地図状の構図を避け、正式地図にない目立つランドマークを追加しない。

### 村の入口

- 村の入口は橋のみとし、「ととのい村」の木製看板は橋の手前の道端に置く。
- 橋を渡ってすぐ中央広場がある。
- 入口視点は橋の手前に立つ人物の低い目線を基本とし、橋の向こうには中央広場の一部だけを見せる。
- 中央広場の中心要素は、昔から使われている石組みの屋外たき火跡とする。
- 中央広場の中央に大木を追加しない。
- 橋を渡った左側には住宅、畑および庭の一部が見えてよい。
- 橋を渡った右側には住宅を置かず、草地、低木および森へつなげる。
- 入口から村全体が俯瞰できる構図にしない。

## 7. 文字とロゴ

- セリフ、効果音、看板文字など、指定された文字だけを生成する。
- 文字列はプロンプトへ一字一句そのまま記載する。
- 指定のないタイトル、話数、説明文、透かしまたは装飾文字を追加しない。
- Official Logo v1を画像生成AIに描かせない。
- ロゴが必要な場合は `STYLE_GUIDE.md` に従い、正式PNGを後工程で合成する。
- ロゴの用途、比率、配色および文字部分を変更しない。

## 8. 編集と修正

- 一部修正では元画像を編集対象として明示し、維持する要素を変更禁止事項として具体的に指定する。
- 構図修正では、カメラ位置、視線の高さ、画角、被写体の大きさ、地平線およびトリミングのうち維持する項目を明記する。
- 地理の修正は見える風景だけを変更し、必要がない限り視点や画角を変更しない。
- 修正途中の画像は正式画像と区別し、正式採用前に上書きしない。

## 9. 保存とGit運用

- 正式採用画像とレビュー画像を分け、生成途中の候補画像を正式版としてコミットしない。
- `git add .` および `git add -A` を使用しない。
- コミット対象ファイルだけを個別にステージする。
- 既存の未追跡レビュー画像を削除、移動またはコミットしない。
- コミットおよびPUSHは、ユーザーから明示的な指示がある場合だけ行う。
